# Zephyr MD pairing and Render deployment

The main service (`npm start`) serves the pairing website at `/` and the bot APIs from the same Express server. It requests real WhatsApp pairing codes and persists linked sessions under `sessions/<number>/`. Linked sessions are restored on server restart and reconnect after transient disconnects.

The standalone `pairing-server.js` remains available when you want an API-key-protected pairing API on a separate port. Its API routes require `PAIRING_API_KEY`; the public website is intended to run through `npm start`.

## Start securely

Set a long random API key and start the service:

```bash
export PAIRING_API_KEY='replace-with-a-long-random-secret'
export PAIRING_PORT=15449
npm run start:pairing
```

Do not expose the service publicly without TLS or a reverse proxy. Keep the API key server-side and never place it in a browser bundle.

## Generate a real pairing code

```bash
curl -X POST http://127.0.0.1:15449/api/pair \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: replace-with-a-long-random-secret' \
  -d '{"number":"27621834910"}'
```

The response contains a `code`. On the target WhatsApp account, open **Settings → Linked Devices → Link a Device → Link with phone number instead**, then enter the returned code before it expires.

## Monitor and remove sessions

```bash
curl -H 'X-API-Key: ...' 'http://127.0.0.1:15449/api/pair/status?number=27621834910'
curl -H 'X-API-Key: ...' 'http://127.0.0.1:15449/api/pairs'
curl -X DELETE -H 'X-API-Key: ...' -H 'Content-Type: application/json' \
  -d '{"number":"27621834910"}' http://127.0.0.1:15449/api/pair
```

The service includes API-key authentication, constant-time key comparison, request rate limiting, input validation, disabled Express fingerprinting, health checks, graceful shutdown, and automatic restoration of saved sessions. The code is generated by WhatsApp; the server no longer sends a fixed custom code.

## Render

Use the included root `render.yaml`, or set the service start command to `cd zephyr-bot && npm start`. The Render disk is mounted through `ZEPHYR_STORAGE_DIR`, so `session/`, `sessions/`, and `data/` survive restarts; without persistent storage, WhatsApp will require pairing again after a redeploy or restart. Keep `MAIN_PAIR_SECRET` and `PAIRING_API_KEY` in Render environment variables, never in the repository.
